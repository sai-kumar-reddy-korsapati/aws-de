How to Think in a Coding Round

Interviewers are not only checking whether your code works. They are watching how you get there. This lesson is the method: what they score, the steps to follow, how to turn a brute force into an optimal solution, and what to say at each moment.

The senior-level extra

At 6 years, interviewers also look for engineering judgment: memory on large inputs, bad records, and how the logic would scale (Spark, partitioning, streaming). One sentence on scale at the end of each answer covers this.

The 7-step method

Use the same steps for every problem. Practising them on every problem in this workbook makes them automatic, which frees your mind for the actual problem under pressure.

  1. Listen and restate (1 min). Repeat the problem in your own words. "So I get a list of records and I need the newest per id, right?" This catches misunderstandings early.
  2. Clarify (2–3 min). Ask about input size, sorted or not, duplicates, empty input, negative numbers, nulls, what to return, and whether you may modify the input. Each problem page lists the questions that matter for it.
  3. Examples (2 min). Write one normal example and one edge case. Work out the expected answer by hand. This turns a vague problem into a concrete one.
  4. Brute force (2 min). Say the simplest correct idea and its Big-O. Do not code it unless asked. "The simplest approach checks every pair, O(n²). Let me see if I can do better."
  5. Optimise (5–10 min). Find the bottleneck and pick a technique (see the levers below). State the new complexity. Get agreement before coding: "I'm planning to use a hash map for O(n). Shall I code that?"
  6. Code (10–15 min). Talk while you type. Use clear names. Handle edge cases at the top. If you are unsure of a library detail, say what you assume.
  7. Test (5 min). Trace your example through the code, writing variable values as you go. Then run the edge cases mentally. Finish with time and space complexity and one sentence on scale.

Turn constraints into a target complexity

The input size tells you how fast the solution needs to be. A computer does roughly 10⁷–10⁸ simple operations per second, and interview tests usually allow about one second.

A full worked example, spoken

Here is how a strong answer to Top K Frequent Elements sounds from start to finish. Notice the rhythm: clarify, brute force, bottleneck, pattern, agreement, code, test, scale.

Interviewer Given a list of numbers and k, return the k most frequent.

You So I return the k values that appear most often. A few questions: can there be ties at the boundary? Does the output order matter? How large is the list?

Interviewer Assume no ties, any order, up to 10⁵ elements.

You Example: [1, 1, 1, 2, 2, 3] with k = 2 gives [1, 2]. With 10⁵ elements I want O(n log n) or better. First step is clearly counting, so I'd use a Counter, which is O(n). Then I need the k largest counts. The simplest way is to sort the distinct values by count, O(m log m). A heap of size k improves that to O(m log k). And since counts are at most n, I could even bucket by frequency for O(n). I'll code the heap version unless you'd like the bucket one?

Interviewer Heap is fine.

You (coding) I count with a Counter, then heapq.nlargest(k, counts, key=counts.get), which keeps a heap of size k internally… Let me trace: counts are {1: 3, 2: 2, 3: 1}, nlargest with k = 2 gives 1 and 2. Edge cases: k equals the number of distinct values returns everything; negative numbers are fine since the Counter doesn't care.

You Overall O(n + m log k) time and O(m) space. If this were billions of events per day in S3, I'd do the same in Spark: group by value, count, then a window with ROW_NUMBER to get the top k per day.

When you are stuck

Getting stuck is normal and interviewers expect it. What matters is how you get unstuck. Work through this list out loud:

  1. Go back to the brute force. Write it if needed. A working slow solution is worth far more than no solution.
  2. Ask "what am I repeating?" and walk through the six levers above.
  3. Try a smaller or special case: what if the array were sorted? What if all numbers were positive? What if k = 1?
  4. Work an example by hand very slowly and notice what your brain does. That is often the algorithm.
  5. Think about the output first: what data structure would make producing the answer trivial?
  6. Ask for a hint gracefully: "I'm thinking about a hash map but I'm not sure what the key should be. Am I on the right track?" Taking a hint well is a positive signal, not a failure.

The bugs that appear most often

  • Off-by-one in loops and binary search bounds (< vs <=, hi = mid vs mid - 1).
  • Forgetting the last group or batch after a loop ends.
  • Modifying a list while iterating over it.
  • Using list.pop(0) (O(n)) instead of deque.popleft().
  • Mutable default arguments (def f(x, acc=[])).
  • [[0] * n] * m creating m references to the same row.
  • Integer division: // floors toward minus infinity (-7 // 2 == -4); use int(a / b) to truncate.
  • Comparing objects in a heap when values tie (add an index as a tie-breaker).
  • Recursion depth over ~1000 on large inputs (switch to an explicit stack or BFS).

Dicts & Sets

The single most important data structure for coding rounds. A dict maps keys to values with O(1) average lookup. A set is a dict with only keys.

Why lookups are O(1): hashing

Python runs a hash function on the key, which turns it into a number that points to a slot in an internal array. Finding a key means computing its hash and jumping straight to that slot, no scanning. That is why keys must be immutable (str, int, tuple), never lists.

Generators & Iterators

A generator produces values one at a time, only when asked. It is how you process a file bigger than your memory.

yield vs return

return hands back one value and the function ends. yield hands back a value and pauses; the next request resumes right after the yield.

Generator expressions

Same as a list comprehension but with round brackets. Nothing is stored; each value is computed on demand.

A list of one million ints holds roughly 8 MB of pointers plus the int objects. The generator holds about 200 bytes regardless of size.

Building a streaming pipeline

Chain small generators like stages of an ETL. Each line flows through all stages before the next line is read, so memory stays flat.

Batching a stream

Python 3.12 ships itertools.batched, which yields tuples. Writing it yourself is a common interview ask.

Concurrency: Threads, Processes & asyncio

"How would you download 10,000 S3 files faster?" is a very common DE interview question. The answer depends on one distinction: is the work waiting on I/O, or burning CPU?

The GIL in one paragraph

CPython has a Global Interpreter Lock: only one thread runs Python bytecode at a time. So threads do not speed up CPU-heavy Python code. But a thread waiting on the network or disk releases the GIL, so other threads run meanwhile. That is why threads are great for I/O and useless for number crunching in pure Python. (Python 3.13 ships an experimental free-threaded build without the GIL, but standard builds still have it, so interview answers should assume the GIL.)

Process gotchas

Arguments and results are pickled to move between processes, so pass small things (paths, not file contents) and avoid lambdas. Always guard with if __name__ == "__main__":.

asyncio basics

async def defines a coroutine; await pauses it while waiting so the event loop can run others. asyncio.gather runs many at once. A Semaphore limits concurrency so you do not overwhelm an API.

Never block the event loop

Calling a normal blocking function (like a boto3 call or time.sleep) inside a coroutine freezes every task. Use async libraries, or push blocking calls to a thread with await asyncio.to_thread(func, args).

Shared state and locks

Better than locks: avoid shared state. Have each task return its result and combine results in the main thread, or use a queue.Queue to pass work between threads.

Interview questions on concurrency

Why don't threads speed up CPU-bound Python?

The GIL lets only one thread execute Python bytecode at a time. Threads help when they spend time waiting (I/O), because waiting releases the GIL. For CPU-bound work, use processes, or libraries that release the GIL in C code (NumPy, many compression libraries).

How would you speed up a Glue Python Shell job that copies 20,000 small S3 files?

It is I/O-bound, so a ThreadPoolExecutor with 32–64 workers and a shared boto3 client with a matching connection pool. Use copy_object (server-side copy, no download), collect failures for retry, and log progress. If it grows further, use S3 Batch Operations or a Spark job, and consider compacting the small files into fewer large ones.

Threads vs processes vs asyncio in one sentence each?

Threads: simple concurrency for I/O with shared memory. Processes: true parallelism for CPU work, separate memory. asyncio: very cheap concurrency for many I/O tasks in a single thread, but needs async-aware libraries.

What is a race condition and how do you prevent it?

Two threads read-modify-write the same data and one update is lost. Prevent it with a lock around the critical section, by using thread-safe structures like queue.Queue, or best, by not sharing mutable state (return results instead).

Connect the dots

Lambda functions are often I/O-bound (calling S3, DynamoDB, APIs), so a thread pool inside one invocation can cut its duration and cost. Glue Spark jobs parallelise across executors instead; you would not add thread pools there for data processing.

35 Verbal Python Questions

Before or between coding problems, DE interviewers fire quick conceptual questions. Each answer below is short enough to say in 30–60 seconds. Tap a question, answer it out loud first, then compare.

Data types and memory

1. List vs tuple: what is the difference and when do you use each?

Lists are mutable, tuples are immutable. Tuples are slightly faster and smaller, and because they are immutable (and hashable when their contents are), they can be dict keys or set members. Use a tuple for a fixed record like (region, month) used as a group key; use a list for a collection you will append to.

2. Mutable vs immutable types? Why does it matter?

Immutable: int, float, str, tuple, frozenset, bytes. Mutable: list, dict, set, most objects. It matters because mutable objects passed to functions can be changed by them, mutable defaults are shared between calls, and only immutable (hashable) objects can be dict keys.

3. is vs ==?

== compares values (calls __eq__); is checks whether two names point to the same object. Use is only for singletons like None: if x is None. Small ints and some strings are cached, so is can appear to work on them, which is a trap.

4. Shallow copy vs deep copy?

A shallow copy (list(x), x.copy(), copy.copy) creates a new outer container but shares the inner objects. A deep copy (copy.deepcopy) recursively copies everything. With nested dicts like a JSON config, modifying a shallow copy's inner dict also changes the original.

5. How does a dict work internally, and why is lookup O(1)?

A dict is a hash table: the key's hash() picks a slot in an array, and collisions are resolved by probing other slots. Lookup computes the hash and jumps to the slot, so it is O(1) on average (O(n) only in pathological collision cases). Since Python 3.7, dicts preserve insertion order as a language guarantee.

6. What makes an object usable as a dict key?

It must be hashable: have a __hash__ that never changes during its lifetime and an __eq__ consistent with it (equal objects must have equal hashes). Immutable built-ins qualify; lists and dicts do not. Frozen dataclasses and tuples of hashables do.

7. How does Python manage memory? What is garbage collection?

Mainly reference counting: each object tracks how many references point to it and is freed immediately when the count hits zero. A separate cyclic garbage collector (the gc module) finds groups of objects that reference each other but are unreachable. Large intermediate lists are a common cause of high memory in pipelines, which is why generators matter.

8. What does __slots__ do?

It declares a fixed set of attributes, so instances do not get a per-instance __dict__. That saves memory when you create millions of small objects (for example, records in a Python Shell job) and prevents adding unexpected attributes.

Functions and scope

9. What are *args and **kwargs?

*args collects extra positional arguments into a tuple; **kwargs collects extra keyword arguments into a dict. They are used for flexible APIs and for wrappers like decorators that pass everything through: func(*args, **kwargs).

10. What is the mutable default argument problem?

Default values are evaluated once, when the function is defined. A default list or dict is therefore shared across calls and accumulates data. Use None as the default and create the object inside the function.

11. What is a closure? What is the late-binding gotcha?

A closure is an inner function that remembers variables from its enclosing scope. Gotcha: closures capture variables, not values, so [lambda: i for i in range(3)] all return 2. Fix with a default argument: lambda i=i: i.

12. global vs nonlocal?

global x lets a function assign to a module-level x; nonlocal x lets an inner function assign to a variable of its enclosing function (used in closures and recursive helpers that update a running best).

13. What is a decorator? Give a real use.

A function that takes a function and returns a wrapped version, applied with @name. Real uses: retry with backoff around AWS calls, timing and logging each pipeline step, caching with lru_cache, input validation. Use functools.wraps so the wrapper keeps the original name and docstring. See the Functions lesson.

14. What is lambda, and when should you avoid it?

An anonymous one-expression function, ideal for key= arguments: sorted(rows, key=lambda r: r["ts"]). Avoid it for anything multi-step or reused; a named def is clearer and shows up properly in stack traces.

Iteration

15. Iterator vs iterable vs generator?

An iterable can produce an iterator (__iter__): lists, dicts, files. An iterator produces values one at a time with __next__ and is consumed once. A generator is an easy way to write an iterator, using a function with yield or a generator expression.

16. Why use generators in data pipelines?

They are lazy: values are produced one at a time, so memory stays constant regardless of input size. You can chain them into a streaming pipeline (read → parse → filter → batch) and process files much larger than RAM, for example inside a Glue Python Shell job.

17. What does yield from do?

It delegates to another iterable, yielding each of its values: yield from child() replaces for x in child(): yield x. Useful for recursive generators such as walking nested folders or JSON.

18. List comprehension vs map/filter vs a for-loop?

Comprehensions are the idiomatic, readable choice for building a list from a transform and a filter, and are usually a bit faster than an equivalent loop with append. map is fine with an existing function. Use a plain loop when there is complex logic, side effects or error handling.

Classes

19. @staticmethod vs @classmethod vs instance method?

An instance method gets self. A classmethod gets cls and is typically an alternative constructor (S3Path.from_uri(...)). A staticmethod gets neither; it is a utility function that lives in the class namespace for organisation.

20. __init__ vs __new__?

__new__ creates and returns the instance; __init__ initialises it. You almost never override __new__, except for immutable subclasses (of str or tuple) or singletons.

21. What is the MRO, and how does super() work with multiple inheritance?

The Method Resolution Order is the order Python searches classes for an attribute (C3 linearisation, visible via Class.__mro__). super() calls the next class in the MRO, not simply "the parent", which is what makes cooperative multiple inheritance (mixins) work.

22. Dataclass vs namedtuple vs plain dict for records?

A dict is flexible but has no schema or typo protection. A namedtuple is immutable and light. A dataclass gives typed fields, defaults, generated __init__/__repr__/__eq__, optional immutability (frozen=True) and slots=True. For pipeline records with validation, dataclasses (or pydantic) are the usual choice.

23. What is duck typing?

Code relies on what an object can do rather than its type: anything with read() can be treated like a file. That is why a function written for a file object also works with io.StringIO or an S3 StreamingBody.

24. What is an abstract base class and why use one?

A class from abc.ABC with @abstractmethods that subclasses must implement; it cannot be instantiated itself. It enforces an interface, for example every Extractor must implement extract(), so a pipeline framework can rely on it.

Errors, resources and concurrency

25. try / except / else / finally: when does each run?

try runs first; except runs only if a matching exception occurs; else runs only if no exception occurred; finally always runs, even after return or an unhandled exception. Put cleanup in finally (or better, a context manager).

26. What is a context manager? How do you write one?

An object used with with that guarantees setup and teardown (__enter__/__exit__), such as closing files or releasing connections even on errors. The easy way to write one is @contextlib.contextmanager with a try: yield finally: block.

27. Why is except Exception: pass bad?

It hides every error, including bugs like typos, and lets bad data flow downstream silently. Catch specific exceptions, log them with context, and re-raise or route the bad record to a dead-letter location.

28. What is the GIL? Threads vs multiprocessing?

The Global Interpreter Lock allows one thread to execute Python bytecode at a time. Threads still help for I/O (waiting releases the GIL); for CPU-bound work use multiprocessing. Details in Concurrency.

Practical engineering

29. How do you add third-party libraries to a Glue job?

For Glue 2.0+, pass --additional-python-modules (pip packages or wheel files in S3). Python Shell jobs on Python 3.9 accept it too; older setups shipped .whl/.egg files through --extra-py-files. Pin versions so runs are reproducible, and check the Glue docs for your version.

30. How do you unit-test code that calls AWS?

Keep business logic in pure functions that take data in and return data out, and test them with pytest. For the AWS calls, use moto to fake services in memory or botocore.stub.Stubber/unittest.mock to stub responses. Example in boto3 essentials.

31. logging vs print?

Logging has levels (DEBUG to CRITICAL), timestamps, logger names and configurable handlers, and in Glue/Lambda it lands in CloudWatch with proper levels. Use log.info("rows=%d", n) (lazy formatting) and log.exception() inside except to capture the stack trace.

32. How do you make a pipeline step idempotent?

Running it twice must give the same result as once. Techniques: overwrite a whole partition instead of appending, use MERGE/upsert on a key instead of insert, deduplicate on a business key, and use deterministic output paths and execution names. This makes retries safe.

33. How do you handle a file too large for memory in Python?

Stream it: iterate the file object line by line (or iter_lines() for S3), process in batches with a generator, keep only aggregates in memory, and use chunked readers (pandas.read_csv(chunksize=...), pyarrow batches). If sorting is needed, external sort. If it is truly large, move it to Spark.

34. What are type hints for, if Python does not enforce them?

Documentation, editor support and static checking with tools like mypy, which catch bugs before runtime. They are expected in production code and make interview code read as senior. Example: def chunk(items: list[str], n: int) -> list[list[str]]:.

35. What is the difference between sort() and sorted(), and what does "stable" mean?

list.sort() sorts in place and returns None; sorted() returns a new list from any iterable. Python's sort is stable: equal items keep their original order, which lets you sort by multiple keys in passes (secondary key first, then primary).

How to answer verbal questions

Definition in one sentence, then a concrete example from data work. "A generator yields values lazily, so I use them to stream large S3 files in Python Shell jobs without running out of memory" beats a textbook definition every time.

Hash Map Patterns

The most frequently tested pattern. Trade O(n) memory for O(1) lookups and most O(n²) problems become O(n).

Pattern 1: "have I seen the complement?" (Two Sum)

For each number, the partner you need is target - num. Store what you have seen in a dict of value → index and check for the partner.

Pattern 2: group by a computed key

Group anagrams: words with the same sorted letters belong together. The trick is choosing the right key.

Pattern 3: prefix sums + hash map

Count subarrays that sum to k. A running sum prefix tells you the sum from the start. A subarray ending here sums to k whenever an earlier prefix equals prefix - k.

Trace the second call. Running prefixes are 0 (empty), 3, 7, 0, 3, 4, 7. A subarray sums to 7 whenever two prefixes differ by 7: 7−0 at position 2 gives [3, 4]; at the final 7, both earlier zeros match, giving [3, 1, 3] and the whole array. Three in total.

Pattern 4: set for O(1) existence

Longest run of consecutive numbers in an unsorted list, in O(n). Only start counting from a number whose predecessor is not in the set.

Connect the dots

Two Sum is a self hash join. Group anagrams is GROUP BY on a derived column. Longest consecutive is the SQL "gaps and islands" problem, which you may also see in the SQL round (consecutive login days).

Step 2 · How to think about it

Start with the dumbest correct idea. Try every pair (i, j) and check whether nums[i] + nums[j] == target. That is two nested loops, O(n²).

Find the repeated work. For each number x, the inner loop is really asking one question: "does target - x exist somewhere in the list?" Scanning a list to answer "does it exist?" costs O(n). A hash map answers the same question in O(1).

So change the question. Walk the list once. For each number, compute its partner need = target - x. If need is already in a dict of numbers seen so far, you are done. If not, store x with its index and move on.

Why store after checking, not before? If you stored first, [3, 2, 4] with target 6 would match the 3 with itself. Checking first guarantees the partner came from an earlier index.

Keywords that should trigger this pattern: "pair", "two numbers", "sum to", "difference equals". Whenever you hear "find a partner for each element", think hash map of what you have seen.

Two nested loops. The inner loop starts at i + 1 so each pair is checked once and an element is never paired with itself.

Follow-up questions

What if the array is sorted?

Use two pointers from both ends: O(n) time and O(1) space. See Two Sum II.

Return all pairs, not just one?

Use a Counter of values. For each distinct value x, pair it with target - x; handle x == target - x by needing a count of at least 2. Avoid double counting by only taking x <= target - x.

Graphs & Topological Sort

A graph is nodes connected by edges, with cycles allowed. For data engineers, the killer application is ordering jobs in a dependency DAG.

Representing a graph

Use an adjacency list: a dict from each node to the nodes it points to.

BFS and DFS on a graph

Same as trees, with one addition: a visited set, because cycles would otherwise loop forever.

Topological sort (Kahn's algorithm)

Order the jobs so every job runs after all of its dependencies.

  1. Count each job's incoming edges (its in-degree = number of unmet dependencies).
  2. Put every job with in-degree 0 in a queue; they can run now.
  3. Pop a job, append it to the order, and decrement the in-degree of the jobs that depend on it. Any that hit 0 join the queue.
  4. If the order is shorter than the job list, some jobs never reached 0: there is a cycle.

O(V + E) time. A natural follow-up: "which jobs can run in parallel?" Answer: every job that is in the queue at the same moment. Process the queue level by level to get parallel stages: [['extract'], ['clean', 'enrich'], ['load'], ['report']].

Step 2 · How to think about it

Use this problem to learn the 4-step DP recipe. Say these steps in every DP interview: 1. State: ways(i) = number of ways to reach step i. 2. Going from recursion → memo → table → two variables is exactly the progression interviewers want to see.

Step 2 · How to think about it

Greedy fails in general: with coins [1, 3, 4] and amount 6, greedy takes 4 + 1 + 1 (3 coins) but 3 + 3 is 2 coins. Always mention a counter-example before choosing DP.

DP recipe: 1. State: dp[x] = fewest coins to make amount x. 2. Transition: the last coin used was some c. Then dp[x] = 1 + dp[x - c]. Try every coin and take the minimum. 3. Base: dp[0] = 0. How to make it stick: spaced repetition

  1. Day 0: solve it (with help if needed). Write the one-line hook in a notebook.
  2. Day 2: re-solve from a blank file without looking. If you fail, read the "How to think" section again, not the code.
  3. Day 7: re-solve against a 20-minute timer, speaking out loud.
  4. Day 21: just recall the approach from the hook and say the complexity. Code it only if you hesitate.

Understanding why the optimal approach works (the "How to think" section) is what lets you solve new variations in the interview. Memorised code without the reasoning collapses under a small twist.

Mistakes that cost senior candidates offers

  • Coding immediately without clarifying, even if the code ends up right.
  • Long silences. Think out loud, even when unsure.
  • Jumping to a clever optimal solution without stating the brute force, then getting stuck with nothing working.
  • Not stating Big-O, or getting x in list wrong (it is O(n)).
  • Not testing: saying "I think it works" instead of tracing an example.
  • Reaching for pandas or Spark when the question is clearly about plain Python logic.
  • Never connecting the answer to real systems. At 6 years, that link is part of what you are hired for.

The day before

  • Sleep. Tired brains make off-by-one errors.
